Audiophile Admin Dashboard Sync Notes

What changed
- The admin dashboard now uses the FastAPI product API as the source of truth.
- The storefront and the dashboard both read from the same FastAPI-backed product data.
- The dashboard brand label stays professional as Audiophile with a smaller Admin label.
- The catalog health card now shows the actual product thumbnail instead of a stock bar.
- Hidden now means not shown on the storefront.

Data flow
- FastAPI product routes live in `backend/main.py`.
- Storefront reads product data through `app/lib/products.server.ts`.
- The client-safe storefront constant `API_BASE_URL` still lives in `app/lib/products.ts`.
- Admin create, update, delete, and duplicate actions call the FastAPI `/products` endpoints.
- Sync refreshes the admin state from the same FastAPI product source.

Admin behavior
- Product list actions now work end to end.
- The middle action duplicates a product as a draft copy.
- The new product form supports image upload and stores the preview image through the product API.
- The visibility picker includes Live, Draft, and Hidden.
- Hidden products are stored but not rendered on the public storefront.

Storefront behavior
- Category and product pages now render dynamically so catalog changes show without rebuilding.
- Only Live products are returned to storefront pages.
- Uploaded or replaced images are used in the dashboard preview and in the shared record.

Backend note
- The existing FastAPI file in the repo now includes GET, POST, PUT, and DELETE product routes in addition to the Stripe checkout endpoints.
- If your production backend already lives elsewhere, copy the same product CRUD shape into that service so both apps stay aligned.

Verification
- Production build completed successfully with `npm.cmd run build`.
